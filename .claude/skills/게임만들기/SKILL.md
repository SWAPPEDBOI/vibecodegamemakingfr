# 게임만들기 — 서브에이전트 파이프라인

**이 문서를 읽는 당신이 오케스트레이터입니다.** 직접 게임 코드를 쓰지 마세요.
아래 4명에게 순서대로 일을 시키고, 결과를 넘겨주는 역할만 합니다.

| 역할 | 에이전트 | 만드는 파일 |
|---|---|---|
| 플래너 | `game-planner` | `PLAN.md` |
| 비주얼 디자이너 | `game-artist` | `STYLE.md` |
| 코더 | `game-coder` | `game.html` |
| 리뷰어 | `game-reviewer` | `REVIEW.md` |

호출은 Agent 툴의 `subagent_type`에 위 이름을 넣습니다.
**서브에이전트는 대화 내용을 모릅니다. 프롬프트에 항상 폴더 절대경로를 쓰세요.**

## 폴더

```
<게임폴더>/
├─ game.html   ← 완성품 (코더만 씀)
├─ PLAN.md     ← 계획
├─ STYLE.md    ← 색·도형
└─ REVIEW.md   ← 검사 결과
```

폴더는 **현재 작업 폴더 아래 `games/<게임이름>/`**. 없으면 만드세요.
서브에이전트에게 넘길 때는 반드시 절대경로로 바꿔서 넘기세요.

## 파이프라인 (순서대로 5단계)

1. **플래너** — "이 폴더(<절대경로>)에 PLAN.md를 써라. 게임 아이디어: <args>"
2. **비주얼 디자이너** — "<절대경로>/PLAN.md를 읽고 같은 폴더에 STYLE.md를 써라"
   → 여기서 PLAN.md를 읽고 사용자에게 **3줄로 요약해 보여준 뒤 진행 여부를 물어보세요.**
3. **코더** — "<절대경로>의 PLAN.md와 STYLE.md를 읽고 game.html을 만들어라"
4. **리뷰어** — "<절대경로>의 game.html을 검사하고 REVIEW.md를 써라"
5. **FAIL이면 코더 1회 재호출** — "REVIEW.md의 항목만 고쳐라". **재시도는 딱 1번.**
   두 번째도 FAIL이면 멈추고 남은 문제를 사용자에게 알리세요.

## 토큰 절약 규칙 (중요 — 학생 계정은 사용량 제한이 있습니다)

- 질문은 **최대 1개**. 애매하면 알아서 정하고 진행하세요.
- 에이전트는 **위 5번 이외에 재호출하지 마세요.** 총 호출 4~5회.
- 파일 내용을 대화창에 통째로 붙여넣지 마세요. 요약만.
- 게임은 `game.html` **한 파일, 200줄 이내**. 기능 추가 요청이 와도 계획에 있는 것만.
